# 电商商详页流量归因数据需求开发技术文档

## 1. 需求概述

### 1.1 业务背景
电商平台需要分析用户从不同入口（首页营销、搜索、推荐页）到达商详页的流量路径，以便优化营销策略和用户体验。通过流量归因分析，可以了解各渠道的转化效果，为业务决策提供数据支持。

### 1.2 需求目标
- 构建完整的用户行为路径数据模型
- 实现商详页流量归因分析
- 提供各入口渠道的转化率分析
- 支持实时和离线数据查询

### 1.3 需求范围
- 数据源：点击日志表、页面浏览日志表
- 分析对象：商详页访问用户
- 时间范围：支持历史数据和实时数据
- 分析维度：用户、商品、渠道、设备、平台

## 2. 技术架构

### 2.1 整体架构
```
数据源层 -> ODS层 -> DWD层 -> DWS层 -> ADS层
    |         |        |        |        |
    |         |        |        |        |
  原始数据   清洗数据   路径构建   归因计算   应用数据
```

### 2.2 技术选型
- **数据存储：** HDFS + Hive
- **计算引擎：** Spark SQL
- **数据格式：** Parquet
- **压缩算法：** SNAPPY
- **调度系统：** Airflow
- **监控系统：** Prometheus + Grafana

### 2.3 数据流向
1. 原始数据从业务系统采集到ODS层
2. ODS层数据进行清洗和标准化处理
3. DWD层构建用户行为路径
4. DWS层计算流量归因
5. ADS层生成应用数据

## 3. 数据模型设计

### 3.1 分层设计
- **ODS层：** 存储原始数据，保持数据完整性
- **DWD层：** 清洗和整合数据，构建用户行为路径
- **DWS层：** 计算流量归因，生成汇总数据
- **ADS层：** 提供应用数据服务

### 3.2 表结构设计
详见 `sql/ddl/create_tables.sql` 文件

### 3.3 字段映射
| 源表字段 | 目标表字段 | 转换规则 |
|----------|------------|----------|
| uid | uid | 直接映射 |
| sid | sid | 直接映射 |
| ts | ts | 直接映射 |
| page_type | page_type | 直接映射 |

## 4. 开发规范

### 4.1 编码规范
- 使用标准SQL语法

- 表名使用层级_业务域_功能描述格式
- 注释完整，说明业务含义

### 4.2 命名规范

## 5. 部署说明

### 5.1 环境要求
- **Hadoop版本：** 3.2.0+
- **Hive版本：** 3.1.0+
- **Spark版本：** 3.2.0+
- **Java版本：** 1.8+
- **内存要求：** 最小8GB，推荐16GB+
- **存储要求：** 最小100GB，推荐500GB+

### 5.2 部署步骤
1. 创建HDFS目录结构
2. 执行DDL语句创建表结构
3. 配置ETL脚本参数
4. 设置调度任务
5. 配置监控告警

### 5.3 配置说明
- **Hive配置：** 启用动态分区，设置最大分区数
- **Spark配置：** 启用自适应查询，优化资源使用
- **调度配置：** 设置ETL执行时间和依赖关系
- **监控配置：** 设置数据质量监控和性能监控

## 6. 监控告警

### 6.1 监控指标
- **数据质量指标：** 数据量、空值率、重复率
- **性能指标：** 执行时间、资源使用率
- **业务指标：** 商详页访问量、转化率

### 6.2 告警规则
- **数据质量告警：** 空值率超过10%时告警
- **性能告警：** 执行时间超过1小时时告警
- **业务告警：** 商详页访问量异常时告警

## 7. 维护手册

### 7.1 日常维护
- 监控ETL任务执行状态
- 检查数据质量报告
- 优化查询性能

## 8. 数据血缘关系

### 8.1 数据流向图
```
点击日志表 -> ODS层点击日志表 -> DWD层用户行为路径表 -> DWS层流量归因表 -> ADS层汇总表
页面浏览日志表 -> ODS层浏览日志表 -> DWD层用户行为路径表 -> DWS层流量归因表 -> ADS层汇总表
```

### 8.2 依赖关系
- ODS层依赖原始数据源
- DWD层依赖ODS层数据
- DWS层依赖DWD层数据
- ADS层依赖DWS层数据
